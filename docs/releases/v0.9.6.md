# Release 0.9.6

Version 0.9.6 tightens release and Rust tooling, moves model routing and contracts to a single Rust source of truth, and cleans up public APIs and shared helpers so packages stay consistent across AppKit, Mastra, auth, and tunnel workflows.

### Model serving and contracts
- Model classification, fuzzy ranking, and capability policy now live in the Rust `model` crate; TypeScript and browser packages consume generated bindings and contracts instead of maintaining parallel logic.
- Handwritten shared-model classification and Open Responses mirrors were removed; schemas and contracts are generated from Rust.
- `@dbx-tools/model` resolves endpoints through native bindings with an updated catalogue and fallback behavior.

### Lakebase, Postgres, and core
- Lakebase address parsing and related types flow through generated `core-rs` bindings; AppKit and Postgres packages align on the same native contract.
- Python `dbx_tools.core` config and advisory-lock behavior stay aligned with the Node equivalents.

### AppKit, Mastra, and plugins
- AppKit gains clearer plugin registry, tool execution, migration, and brand-context modules; Lakebase resolution uses native address parsing.
- AppKit-Mastra drops a custom pagination helper and leans on native Mastra memory APIs; serving and chart paths follow updated model and brand utilities.
- App environment detection is aligned across core config utilities (Node and Python).

### Auth and tunnel
- Shared auth contracts centralize route and client helpers; auth-gate and UI auth consume the same browser-safe surface.
- Tunnel adds a built login client asset, gate and plugin updates, and tests for the Node adapter; auth routes and model-related caches are isolated for safer runtime behavior.

### Native binaries and release
- Rust release tooling moves from a dedicated `release-tools` crate into Projen-generated Node helpers (`rust-release.mjs`), with hardened archive validation and clearer separation from UniFFI binding workflows.
- `@dbx-tools/rust-binary` is renamed around release-binary installation; the CLI no longer embeds duplicate rust-binary wiring.
- Projen supports standalone Rust projects; release and build workflows, tasks, and tests were expanded accordingly.

### Model proxy observability
- The embedded metrics dashboard gets consistent widget padding, updated assets (including uPlot), and richer request logging on the proxy side.

### Shared utilities and API shape
- Shared-core modules use filename-derived namespaces (`async-utils`, `brand-utils`, `config-utils`, and similar) with new bounded async mapping helpers.
- Deprecated compatibility surfaces were removed across the monorepo; barrels and exports follow capability-specific module names.
- Docs scripts reuse shared repository utilities; README and agent docs describe project-root resolution and naming conventions.

### Documentation and quality
- Enhancement plans and a repository code-quality audit were added or archived; source-doc baselines and checks were updated for the new export layout.
- Path ignore behavior and docs sync stay independent of native binding generation so everyday JS and docs work does not require a Rust rebuild.
