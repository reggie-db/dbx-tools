## v0.9.172
Cumulative changes from `v0.9.167` through HEAD and the working tree, including failed release attempts `v0.9.168`–`v0.9.171`.

**Breaking Changes**
- `ModelCapabilities` now requires `reasoning`, `tools`, `structuredOutput`, and `temperature`. Update manually constructed objects and serialized payloads.
- Model Gateway rejects nonnumeric temperatures with HTTP 400. For recognized Databricks models with published policy, unsupported temperatures are removed and supported values are clamped to 0–2. Unknown custom endpoints retain finite numeric values.

**Improvements And Fixes**
- Model discovery incorporates models.dev capabilities and modelparams.dev reasoning levels, with offline fallbacks.
- Published reasoning levels take precedence over learned errors. Explicit null, disabled, or invalid efforts map to a supported level nearest medium; omitted fields remain unchanged. Gateway requests retry once without reasoning when upstream explicitly rejects it.
- Service installation isolates binaries and Python environments per installation, serializes concurrent installs, and skips satisfied runtime dependencies. Reinstall existing services to apply these changes.
- macOS services use LaunchAgent lifecycle controls and clear persisted disabled overrides. Tray initialization failures or tray exits no longer stop the managed service.
- Fix Model Gateway service compilation failures caused by missing `@mlflow/core`, and correct embedded email-logo attachment handling and Content-ID formatting.
- Release-note generation preserves cumulative unreleased changes across failed release attempts.

**Validation**
- The configured release validation phase completed before this review; detailed outcomes and counts were not supplied. No tests or validation commands were rerun, and no files were modified.
