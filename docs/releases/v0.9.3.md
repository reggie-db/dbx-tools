# Release 0.9.3

dbx-tools 0.9.3 tightens release and versioning for the monorepo: one shared version line, more reliable Rust artifact reuse across platforms, and release preparation that can run through publication completion and recover when something fails mid-pipeline.

### Versioning

- Resolves the singular release version from component tags so npm, PyPI, Cargo, and related surfaces stay aligned on one version number.

### Release workflow and preparation

- Runs release preparation through publication completion instead of stopping earlier in the pipeline.
- Keeps release preparation independent of a specific package registry so local and CI prep are less brittle when registries are slow or unreachable.
- Improves recovery when a release needs to be retried or finished with the current GitHub Actions workflow.
- Selects a GitHub CLI account that actually has write access when multiple accounts are configured on the same host.

### Rust builds and Cargo

- Derives Rust build reuse keys on each target runner so reused binaries match the platform that built them.
- Synchronizes `Cargo.lock` during release prep without requiring registry access in that step.
- Adds macOS Rust checksum support for content-addressed reuse and verification.
- Updates Rust release tooling and generated reuse metadata (`.release/rust-build.json`, projen Rust workspace generation).

### Contributor docs

- Documents singular versioning and content-addressed Rust release behavior in `AGENTS.md`, `projen/README.md`, and the in-repo release enhancement plan.
