# Release 0.9.20

This release rebuilds the npm and PyPI publication pipeline around a simplified draft promotion flow, removing the older release-plan and release-please machinery in favor of a single candidate build and publish path.

## Release Pipeline

- Rebuilt the draft promotion pipeline for npm and PyPI publishing.
- Passed the Python root through to candidate builds so Python packaging resolves correctly.
- Restored npm token publishing after a regression.
- Finalized the npm trust cutover and removed legacy trust bootstrapping.
- Parsed npm collaborator access correctly when probing token permissions.
- Expanded and then simplified the npm token access probe.
- Added recovery automation for current npm publishing issues.
- Made npm publishing tolerant of staged retries.
- Recovered npm provenance bootstrap handling.
- Added bootstrap support for publishing brand new npm packages.

## Removed

- Removed `release-plan.ts`, `release-please.ts`, `release-bootstrap.ts`, `release-request.ts`, `release-summary-units.ts`, and `stamp-python.ts`, along with their tests, as part of consolidating release logic.

## Documentation

- Updated `AGENTS.md` with current release pipeline guidance.
- Rewrote the content-addressed Rust release plan enhancement doc to reflect the simplified pipeline.
- Updated the repository code quality audit enhancement doc.
- Updated the projen README with revised release documentation.
- Updated the example server README and deploy staging script.
