## v0.9.127
Compared HEAD and the working tree against `v0.9.126`; generated churn and test-only changes are excluded.

**Breaking Changes**
- Sandbox projects replace `postinstall` with `install` for persistent preparation and `start` for workload launch. Move cleanup from `config.tasks.uninstall` to the first-class `uninstall` field.
- Project lifecycle failures return `state: "error"` with saved diagnostics instead of failing machine startup; callers must inspect project state.

**Features And Fixes**
- Project installation is configuration-gated; workloads start after installation and once per machine boot. Setup waits for lifecycle completion.
- Persisted project URLs wake stopped Sandboxes on authenticated HTTP requests, showing an auto-refreshing loading page or HTTP 202 JSON while starting.
- Failed setup preserves project files and logs. Machine status and UI indicators reflect ongoing project startup.
- SSH commands default to the execution user’s home directory with matching `PWD`, avoiding inaccessible working-directory failures.

**Validation**
- Configured release validation completed before this review. Detailed outcomes and counts were not supplied; no validation commands were rerun and no files were modified.
