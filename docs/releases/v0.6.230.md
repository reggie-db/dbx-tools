# Release 0.6.230

dbx-tools 0.6.230 simplifies the release process around one repository version while reducing repeated native builds and documentation work.

### Release workflow

- Restores one shared `VERSION` across JavaScript, Python, and Rust packages.
- Adds the local `bun run release` flow, which validates a release branch, opens a pull request to `main`, and enables automatic merge by default.
- Starts publication from the exact merged `main` commit and creates one version tag and GitHub Release.
- Removes the component release manifests, release units, and generated release-request workflow.

### Rust releases

- Adds version-independent Rust build fingerprints for every supported target.
- Reuses a matching raw bundle from an earlier successful GitHub Release and verifies it with SHA-256 before packaging.
- Adds structured cross-platform binary version stamping through the Rust `object` crate, including re-signing patched macOS artifacts.
- Uploads Cargo timing reports when a target must be rebuilt.

### Documentation

- Runs TypeDoc, Python API generation, and Rustdoc concurrently.
- Preserves and caches Rustdoc build state instead of deleting the complete target directory.
- Skips duplicate TypeDoc error checking after the normal TypeScript compile validation.
- Fixes deployment so only successful documentation builds are published.

### Runtime and tooling

- Exposes stamped build information from the shared Rust core.
- Clarifies AppKit initialization and readiness logging.
- Keeps the Graphiti runtime and generated package metadata synchronized with the singular release version.
