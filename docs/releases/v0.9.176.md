## Release Notes

### Features
- Add Databricks Smart Router through the virtual `smart-router` model for Responses, Chat Completions, Anthropic Messages, and Codex. Selection respects protocol and requested capabilities, with routes pinned across tool calls and retries.
- Add file/stdin model selection with `dbx model-gateway --profile PROFILE --select-model-from request.json`, returning the concrete model and routing metadata without starting a server.

### Behavior and Breaking Changes
- Unpinned Mastra HTTP turns now use Smart Router when available; explicit model and model-class choices retain precedence.
- Public `ModelCapabilities` and `RequestedFeatures` schemas now require `imageInput` and `applyPatch` fields.

### Fixes
- Cache and refresh Smart Router availability per identity, and invalidate availability after selection failures. Routed requests fail rather than silently selecting a fallback.
- Preserve reasoning returned in structured Chat Completions content. Mastra applications can hide reasoning streams with `sendReasoning: false`.
- Keep Databricks models distinct from Codex’s bundled catalogue, with GPT-first ordering, newer versions first, and clearer labels.

### Validation
- Configured release validation completed before this review, as reported. No additional validation commands ran.
- Scope covers `v0.9.175..HEAD` plus the working tree; no newer local release tags or release-note files were present.
