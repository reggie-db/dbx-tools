## v0.9.205
Cumulative changes since `v0.9.203`, including the failed `v0.9.204` attempt and working tree.

**Fixes And Improvements**
- Model Gateway recognizes Codex model-list requests with a nonblank `client_version`, even without an `Originator` header.
- Profile-based model discovery reuses profile-isolated catalogue caches and stays on the primary profile when fallbacks are configured. Ordinary inference avoids an unnecessary full registry listing.
- Filesystem, deployment, publishing, and development-watch containment checks accept valid names beginning with `..` while continuing to reject paths outside their roots.
- Python binding generation resolves namespace exports through the TypeScript parser and generates typed records for nested Zod-inferred options.
- Model metadata snapshots and resolved Lakebase connections receive runtime schema validation; Genie completion events reject unsupported status values.

**Breaking Changes**
- `ModelGateway.models()` takes a boolean Codex selector instead of an originator string; `isCodexOriginator()` is replaced by `isCodexRequest(request)`.
- Removed PostgreSQL parsing aliases: import `parseAddress`, `parseResourcePath`, and `parseSslMode` from `@dbx-tools/lakebase`. Use the model `policy` namespace for `isResponsesOnly` and `lmArenaContract` for LMArena constants and types.
- Projen’s `publicNamespaceExports()` returns `{ name, source }` records instead of strings.

**Validation**
- The configured release validation phase completed, as reported. No tests or validation commands were rerun; no validation counts are claimed. No files were modified.
