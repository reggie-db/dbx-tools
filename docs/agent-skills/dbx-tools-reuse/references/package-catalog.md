# dbx-tools package catalog

Generated from repository manifests and package READMEs for dbx-tools 0.9.171.
Inspect the installed manifest, README, exports, and source before relying on a capability.

## CLI tools

- `@dbx-tools/cli` - Use dbx to authenticate with Databricks, connect local PostgreSQL tools to Lakebase, expose workspace models to local clients, run graph memory, and share an application through an access-controlled public URL. Source: `packages/js/cli/dbx-tools`.
- `@dbx-tools/cli-args` - Generate Commander flags, help text, parsed values, and argv from one Zod object schema without installing the full dbx package. Source: `packages/js/cli/args`.
- `@dbx-tools/cli-service` - Add current-user service installation, lifecycle commands, optional uv-managed Python dependencies, and a tray menu to a Commander CLI. The managed command continues after its terminal closes on macOS, Linux, and Windows. Source: `packages/js/cli/service`.

## Node and AppKit

- `@dbx-tools/appkit` - Configure Lakebase before Databricks AppKit plugin startup and use AppKit request context, typed plugin lookup, and Databricks SDK cancellation from backend code. Source: `packages/js/node/appkit`.
- `@dbx-tools/appkit-generator` - Generate researched brand contexts or provision a governed Databricks demo environment from business questions. The package exposes every operation as an AppKit tool and composes them through a registered Mastra workflow. Source: `packages/js/node/appkit-generator`.
- `@dbx-tools/appkit-lakebox` - Give each authenticated Databricks App user a persistent Linux home, terminal, desktop, OCI image services, agent tools, and machine metrics in one shared Databricks Lakebox. Source: `packages/js/node/appkit-lakebox`.
- `@dbx-tools/appkit-mastra` - Host Mastra agents in a Databricks App with AppKit authentication, streaming routes, Lakebase-backed memory, Genie tools, model selection, chart and table embeds, Genie or MLflow feedback, and MCP exposure. Source: `packages/js/node/appkit-mastra`.
- `@dbx-tools/appkit-memory` - Add durable, actor-scoped memory tools to an AppKit application. The plugin checks Databricks Agent Memory first and starts its Graphiti sidecar only when the current actor cannot access the configured managed-memory store. Source: `packages/js/node/appkit-memory`.
- `@dbx-tools/appkit-model-gateway` - Expose models in a Databricks workspace through OpenAI Responses, OpenAI Chat Completions, Anthropic Messages, embeddings, and Codex-compatible APIs. The gateway discovers the workspace catalogue and selects a compatible Databricks route for each request. Source: `packages/js/node/appkit-model-gateway`.
- `@dbx-tools/appkit-web-search` - Add web_search and web_fetch to an AppKit or Mastra backend. web_search runs on the Databricks Model Serving native web-search tool: the model searches the web server-side and returns a synthesized answer plus the sources it used without a third-party search API key. web_fetch reads a single page through got-scraping. Source: `packages/js/node/appkit-web-search`.
- `@dbx-tools/auth` - Resolve Databricks profiles and produce tokens or authentication headers from Node.js and Bun. The package selects personal access token (PAT), machine-to-machine (M2M), CLI user-to-machine (U2M), Databricks App service-principal, or App on-behalf-of-user (OBO) authentication and coordinates token acquisition in process memory. Source: `packages/js/node/auth`.
- `@dbx-tools/auth-gate` - Create a platform-neutral passwordless runtime with Better Auth, email one-time passwords, passkeys, caller-provided identity policy, and persistent storage. Source: `packages/js/node/auth-gate`.
- `@dbx-tools/cache` - Cache Node.js and Bun values in bounded memory with optional project-scoped disk or Keyv-compatible persistence. Foreground writes don't wait for persistence, and shutdown can drain tracked writes. Source: `packages/js/node/cache`.
- `@dbx-tools/core` - Use shared Node and Bun helpers for layered configuration, binary installation, process execution, locking, and project discovery. Browser-safe utilities live in @dbx-tools/shared-core. Source: `packages/js/node/core`.
- `@dbx-tools/databricks` - Resolve Databricks workspace identity, access workspace files, detect cloud and region, resolve DNS, and discover the caller's public IP. Source: `packages/js/node/databricks`.
- `@dbx-tools/databricks-zerobus` - Create a Zerobus SDK client and open ingest streams without constructing the region-specific Databricks endpoint yourself. Source: `packages/js/node/databricks-zerobus`.
- `@dbx-tools/email` - Add model-drafted email with human approval, sender policy, SMTP delivery, and a local development outbox to an AppKit or Mastra backend. Browser-safe message and result schemas live in @dbx-tools/shared-email, and the reusable React Email presentation lives in @dbx-tools/shared-email-template. Source: `packages/js/node/email`.
- `@dbx-tools/fs` - Use the @dbx-tools/shared-fs contract against local disk from Node.js. This implementation adds host separator conversion, Node I/O, symlink containment, and errno mapping to BaseFileSystem. Source: `packages/js/node/fs`.
- `@dbx-tools/genie` - Run Databricks Genie turns from Node or AppKit code as raw message snapshots or a typed event stream. AppKit requests keep their on-behalf-of-user (OBO) identity, standalone callers use the Databricks SDK authentication chain, and both modes support cancellation. Source: `packages/js/node/genie`.
- `@dbx-tools/lakebase` - Resolve a Databricks Lakebase target into the host, database, and user a PostgreSQL client needs, then request a short-lived database credential. The package gives Node and Bun applications a profile-aware path from a project name or resource URL to connection-ready values. When the target is a Lakebase path or URL without a chosen database, discovery picks the branch default (status.default, then Lakebase's provisioned databricks_postgres) instead of PostgreSQL's generic postgres database. Source: `packages/js/node/lakebase`.
- `@dbx-tools/lakebox` - Connect to, provision, and run commands on Databricks Lakeboxes. Source: `packages/js/node/lakebox`.
- `@dbx-tools/model` - Resolve a loose model request such as "claude sonnet" or "chat-fast" to a concrete Databricks Model Serving endpoint in the active workspace. The client lists /serving-endpoints, caches and enriches the catalogue, classifies endpoints by capability, fuzzy-matches names, and falls back to a small static floor when the live catalogue is unavailable. Source: `packages/js/node/model`.
- `@dbx-tools/model-protocol` - Construct Vercel AI SDK ProviderV4 models for Databricks endpoints and translate gateway traffic between supported model protocols. Source: `packages/js/node/model-protocol`.
- `@dbx-tools/path` - Discover, match, ignore, scan, and watch filesystem paths with the same rules used by the CLI, Projen, barrel generation, code generation, and documentation tooling. Source: `packages/js/node/path`.
- `@dbx-tools/postgres` - Use connection-correct PostgreSQL advisory locks and a structured LISTEN/NOTIFY topic bus from Node.js. The package also provides optional message persistence, sender identity, and connection helpers. Source: `packages/js/node/postgres`.
- `@dbx-tools/search` - Add agent tools, federated search, index lifecycle helpers, or a Lakebase-backed full-text provider to AppKit AI Search. Use native AppKit aiSearch for Databricks AI Search queries. Add this package when an agent needs search / universal_search, an app needs to create, sync, or seed indexes, or a deployment needs the same AppKit query contract backed by PostgreSQL full-text search instead of Vector Search. Source: `packages/js/node/search`.
- `@dbx-tools/tunnel` - Expose an application through a public Portr or FRP tunnel with an in-process passwordless access gate from @dbx-tools/auth-gate. Source: `packages/js/node/tunnel`.

## Python

- `dbx-tools-graphiti` - Run Graphiti REST, MCP, model routing, and PostgreSQL-backed graph memory from one Python runtime. Use embedded PostgreSQL for local persistence or connect to an external PostgreSQL or Lakebase database. Source: `packages/py/graphiti`.
- `dbx-tools-node-runtime` - Run dbx-tools Python packages that contain generated PythonMonkey bindings in managed Python environments without a system Node.js or npm installation. Source: `packages/py/node-runtime`.

## Shared contracts

- `@dbx-tools/shared-auth` - Validate passwordless sign-in, passkey, Databricks profile, and resolved-client data at browser and server boundaries. The package also provides browser helpers for the routes owned by @dbx-tools/auth-gate. Source: `packages/js/shared/auth`.
- `@dbx-tools/shared-core` - Use browser-safe utilities shared by @dbx-tools/* packages in browsers, workers, Node, Bun, CLIs, and schema packages. The package includes logging, options, networking, JSON, hashing, predicates, and other dependency-light foundations. Source: `packages/js/shared/core`.
- `@dbx-tools/shared-email` - Validate browser, route, and agent-tool payloads for @dbx-tools/email without importing Node-only code. Source: `packages/js/shared/email`.
- `@dbx-tools/shared-email-template` - Render the same React Email presentation in server-delivered messages and browser previews. The package owns the branded document, card, body, and brand mapping without depending on Databricks AppKit, SMTP, or DOM APIs. Source: `packages/js/shared/email-template`.
- `@dbx-tools/shared-fs` - Use one filesystem contract across memory, local disk, Unity Catalog volumes, and other rooted storage backends. This browser-safe package provides the portable FileSystem interface, BaseFileSystem, normalized errors, path helpers, caching, and an in-memory adapter. Source: `packages/js/shared/fs`.
- `@dbx-tools/shared-generator` - Use browser-safe contracts and streaming clients for @dbx-tools/appkit-generator. Source: `packages/js/shared/generator`.
- `@dbx-tools/shared-genie` - Validate AI/BI Genie wire payloads and derive UI events from raw message snapshots without importing the Databricks SDK. Use the browser-safe schemas, event vocabulary, and snapshot diff helpers in clients, routes, and tests. The Node driver that calls Genie is @dbx-tools/genie. Source: `packages/js/shared/genie`.
- `@dbx-tools/shared-genie-code` - Resolve and validate configuration shared by the managed Genie Code CLI and its local model gateway sidecar without loading either runtime. Use these schemas for option defaults, profile homes, and generated TOML. Source: `packages/js/shared/genie-code`.
- `@dbx-tools/shared-graphiti` - Validate Graphiti configuration consistently in Node, Databricks AppKit, browser tools, and shared JavaScript code. Use the browser-safe schemas, defaults, and environment parser without loading the Graphiti runtime. Source: `packages/js/shared/graphiti`.
- `@dbx-tools/shared-lakebox` - Browser-safe Zod contracts and route builders for the app Lakebox: lifecycle summaries, the current user's account, services, commands, logs, and metrics. Source: `packages/js/shared/lakebox`.
- `@dbx-tools/shared-mastra` - Validate browser-facing data exchanged with @dbx-tools/appkit-mastra. It defines the shared route constants, headers, embed markers, feedback schemas, thread selection fields, published client configuration, and response schemas. Source: `packages/js/shared/mastra`.
- `@dbx-tools/shared-model` - Validate model lookups and ranked model responses in UIs, routes, tools, and tests without importing Databricks clients. Use the browser-safe model selection, capability, reasoning, and OpenAI Chat Completions contracts across client and server boundaries. Server-side normalization, classification, ranking, and fuzzy resolution live in @dbx-tools/model. Source: `packages/js/shared/model`.
- `@dbx-tools/shared-model-gateway` - Discover models exposed by a dbx-tools model gateway from browser, edge, or shared application code. The package validates success and error responses at the network boundary and provides model-picker contracts without importing Node or Databricks AppKit runtime code. Source: `packages/js/shared/model-gateway`.
- `@dbx-tools/shared-search` - Validate Databricks AI Search requests, results, index catalogs, and document writes in browser and server code. It defines the browser-safe extension contracts shared by @dbx-tools/search, Mastra tools, and @dbx-tools/ui/search. Source: `packages/js/shared/search`.

## React UI

- `@dbx-tools/ui` - Use this React package for the shared Databricks AppKit UI foundation, branding, passwordless authentication, email surfaces, and Databricks AI Search controls. Import only the subpaths that your browser application uses. Source: `packages/js/ui/appkit`.
- `@dbx-tools/ui-lakebox` - Render Lakebox lifecycle controls, user services, and live machine metrics in an AppKit React application. Source: `packages/js/ui/lakebox`.
- `@dbx-tools/ui-mastra` - Add a React chat surface to @dbx-tools/appkit-mastra. The package supports streaming, model selection, AI/BI Genie progress, charts, tables, approvals, history, threads, export, and MLflow feedback. Source: `packages/js/ui/mastra`.
