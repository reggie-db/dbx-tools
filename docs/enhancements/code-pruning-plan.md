# Code Pruning Plan

Generated: 2026-09-09

This is a plan-only audit. It does not authorize the refactors described below.
The only other intentional repository change from this audit records the
requested Bun working preference in AGENTS.md.

## Executive summary

- The clearest package-reduction candidate is to fold cli-auth, cli-appkit-env,
  and cli-tunnel into lazy @dbx-tools/cli subpaths. The root CLI already installs
  all three, but appkit-env and tunnel also publish non-command APIs and the
  separate packages may still benefit direct consumers. Preserve those APIs and
  prove public usage and install-cost impact before removing a boundary.
- appkit-graphiti currently depends on the entire CLI graph for two native-binary
  helpers. A narrow release-binary runtime would add one justified boundary while
  removing the CLI, tunnel, email, and auth graph from Graphiti. If all three CLI
  packages are consolidated and this owner is published, the potential
  package-count change is net minus two, not a guaranteed reduction.
- @dbx-tools/fs should remain separate. Mastra 1.47 overlaps its local-file
  operations, but the canonical boundary isolates Node APIs behind the shared-fs
  contract and also owns OS-path, scratch, and atomic-rebuild semantics.
- The largest library replacement is the official Databricks Postgres client:
  it can replace roughly 300–450 lines of Node Lakebase REST models, transport,
  one-page list handling, and long-running-operation polling. The Python SDK now
  exposes the same typed Postgres API and can remove another handwritten REST
  layer.
- Zod schemas and TypeScript plugin configuration shapes are maintained twice.
  They have already drifted in three concrete places. Define each configuration
  once in Zod and derive both TypeScript and JSON Schema.
- shared-core contains a public lazy collection mini-framework of roughly 760
  lines used at 15 internal production call sites across eight files in five
  packages. Native arrays, iterators, and Set cover most use; remove it through
  deprecation rather than a flag-day API break.
- Repeated runtime holders, polling loops, process supervision, migration
  initialization, SQL quoting, model snapshot refresh, and cache policy offer a
  further set of smaller, low-risk DRY deletions.
- The explicitly estimated gross opportunity is approximately 1,300–2,005
  production and package-boilerplate lines, with up to two net package removals
  after public-usage validation.
- No Rust or Python distribution should be merged merely for package count.
  Their current boundaries isolate native bindings, optional cloud libraries,
  binaries, SQLAlchemy/Postgres, or Graphiti dependencies.
- No critical defect was found. The main risk is maintenance drift and release
  surface area, not an immediate rewrite or security emergency.

## Architectural mental model

dbx-tools is a generated polyglot monorepo. The projen package and root
.projenrc.ts synthesize a Bun JavaScript workspace, Python distributions, Rust
crates, package manifests, barrels, tests, and one release workflow. JavaScript
is deliberately split into shared browser-safe contracts, Node/AppKit runtimes,
React UI packages, and CLI commands. Rust owns Databricks authentication,
native bindings, model discovery, and two proxy binaries; generated UniFFI
facades expose the appropriate Rust contracts to Node and Python. Python keeps a
dependency-free core plus framework-specific Postgres and Graphiti packages.
See AGENTS.md:797-818, AGENTS.md:804-812, and
docs/enhancements/dry-code-quality-audit.md:12-20.

The useful pruning criterion is therefore not raw package count. A boundary
earns its keep when it prevents a browser, bootstrap path, or optional feature
from installing a heavier runtime. A package that has one consumer and isolates
no dependency should be folded back. That rule is already stated at
AGENTS.md:797-818; this plan applies it to the current dependency graph and to
newer AppKit, Mastra, Databricks SDK, and Google library surfaces.

## Scope and method

- Reviewed 120,810 tracked TypeScript, JavaScript, Python, Rust, shell, and
  documentation-script lines, 39 of 40 tracked packages/js manifests, all five
  Python distributions, and five of six tracked Rust crates.
- Read current architecture and enhancement documents, recent history, the
  largest source files, and six months of churn. The highest recurring churn is
  in .projenrc.ts and projen generation/release code.
- Checked installed AppKit 0.60.0 and its declaration files before judging
  AppKit-facing packages.
- Excluded the then-untracked Databricks OpenAPI/client work from findings so
  the audit did not judge or overwrite in-progress user work. It landed in
  c207ca8d while this plan was finalized.
- cargo check --workspace --all-targets passed for the five audited Rust crates;
  the then-in-progress sixth client was excluded.
- Configured Ruff passes. A targeted stricter scan of generated facades produced
  only expected generated-code diagnostics and no material pruning signal.
- bun audit could not read the current lockfile and exited with
  UnknownLockfileVersion under Bun 1.3.14, so this plan makes no dependency-CVE
  claim.
- knip, madge, depcheck, vulture, pydeps, mypy, pip-audit, cargo-audit,
  cargo-udeps, and cargo-machete were not installed. They were not installed
  globally during the audit.

## Top 5: if nothing else, do these

### 1. F001-F002 — Replace handwritten Lakebase/Postgres transport

Refactor outline:

1. Write transport-independent fixtures for project/branch/endpoint/database
   selection, pagination, cancellation, endpoint state, create races, and
   resource-name normalization.
2. Add the catalogued @databricks/sdk-postgres 0.49.0 client as a direct AppKit
   dependency. Supply an explicit host and request-scoped credentials,
   optionally a custom HTTP client, and disable profile and environment
   resolution.
3. Raise the Python databricks-sdk minimum to 0.81.0 and use
   WorkspaceClient.postgres for Autoscaling calls while preserving the separately
   governed provisioned compatibility path.
4. Delete raw request helpers, local response models already owned by the SDK,
   and LRO polling. Keep only dbx-tools policy.

This removes the highest-risk custom protocol code while retaining the product's
actual value: intent-based connection resolution.

### 2. F003-F004 — Collapse child CLIs and fix Graphiti's dependency edge

Target shape:

    @dbx-tools/cli
      /appkit-env
      /auth
      /tunnel

    @dbx-tools/release-binary
      generated command registry
      platform asset selection
      install/run adapter

First migrate appkit-env's env-export API and tunnel's app/options/proxy APIs,
then publish compatibility packages that re-export the new CLI subpaths. Move
Graphiti to the narrow release-binary package before any old package disappears.
Remove a package only after direct-import and dependency-cost evidence, following
the repository's deprecation window. Consolidating all three yields a potential
net two-package reduction without reintroducing a dependency leak.

### 3. F006 — Make Zod the only plugin configuration contract

For each plugin, replace the handwritten interface plus handwritten JSON Schema
with one Zod schema, z.input for caller input, z.output for resolved output, and
z.toJSONSchema for the AppKit manifest. Start with the three known drift cases,
then apply the same pattern to Teams, search, Mastra, and Graphiti. Snapshot the
generated manifest schemas so an optional/required or string/array change is
reviewable.

### 4. F007-F008 — Retire the shared-core collection framework

Do not replace it with another general utility package. Convert the internal
call sites to native arrays, iterators, and Set; keep a focused generator helper
only where laziness is measured as useful. Separately test deepEqual's comparator
behavior and either retain the small function or adopt a direct tiny library.
Deprecate public exports before removing them. Fix or delete Sequence.join in the
first preparatory change.

### 5. F019-F021, F025 — Consolidate the developer installer around Bun

Keep scripts/install.sh as the small Bun bootstrap and scripts/install.ts as the
mise-backed executable seam. Repair or retire the broken install.mjs path,
delete the QuickJS experiment if it is not supported, and remove the duplicate
shell detection block. npm and pnpm remain valid before Bun exists and in the
documented Databricks deployment and publication paths; routine work after
bootstrap uses Bun. Pin that behavior with an end-to-end DEV_INSTALL fixture and
make contributor hints describe the same ownership.

## Phased pruning roadmap

### Phase 0: baselines and public-usage evidence

- Record packed export maps and dependency trees for every package in scope.
- Search release/download telemetry or repository consumers for direct imports
  of the three child CLI packages, shared-core collection exports, and
  FileLayout::PerCredential.
- Add missing behavior fixtures before swapping SDKs or public implementations.
- Add the missing static-analysis tools as repository dev dependencies only if
  the maintainer wants them recurring; do not depend on one-off global installs.

Exit gate: current behavior is captured and every planned public removal has a
deprecation or explicit breaking-release decision.

### Phase 1: low-risk deletion and contract cleanup

- F006, F008, F012, F014, F016-F021, F023, F025, F027, F029, F033, and
  F036-F042.
- Derive plugin manifests from Zod, beginning with the known drift cases, and
  centralize only the small S-effort helpers in this phase.
- Repair or retire the developer install.mjs path without changing the
  documented Databricks deployment and publication workflows.
- Remove unused dependency declarations one package at a time.
- Delete orphaned QuickJS installer files only after the open question is
  answered.

Exit gate: Bun compile/test/pack checks pass, Cargo workspace checks pass, and
generated manifests show only intended changes.

### Phase 2: shared DRY primitives

- F009-F011, F013, F028, F030-F032, F034-F035, and F044.
- Keep helpers small and located in an existing owner; do not create a new
  generic core crate.
- Delete call-site implementations in the same change that adds each helper.
- Pin public/private IPv4 and IPv6 cases before centralizing the web-fetch SSRF
  policy.

Exit gate: net lines decrease, no helper has only one consumer, and signal,
polling, migration, and cache failure tests cover the centralized behavior.

### Phase 3: maintained-library replacements

- F001, F002, F015, F022, F024, F026, and conditionally F043.
- Replace Node and Python Lakebase protocol layers together so fixtures and
  semantics stay aligned.
- Replace HTML, Markdown, and TOML regex/encoders only after golden output
  fixtures exist; preserve the public generated-enum contract during F026.

Exit gate: SDK/library contract tests pass, cancellation and error mapping remain
stable, and dependency/MSRV costs are measured against deleted code.

### Phase 4: package collapse

- Move native binary install/registry code to its narrow owner and remove the
  Graphiti-to-CLI dependency.
- Publish lazy @dbx-tools/cli subpaths and compatibility packages.
- Remove each old CLI package only after the deprecation window and public-usage
  check; preserve any boundary that still lowers standalone installation cost.

Exit gate: packed installs and CLI help work on supported platforms, Graphiti no
longer installs the CLI graph, and package publication order is simpler.

### Phase 5: public utility retirement

- Deprecate and remove the shared-core collection mini-framework.
- Revisit @dbx-tools/genie only if AppKit gains raw progress snapshots or the
  product deliberately drops intermediate thought/attachment events.
- Apply F005 only after external usage evidence and a breaking-release decision.

Exit gate: no compatibility shims or deprecated exports remain without an owner
and removal release.

## Things that look bad but are actually fine

- Generated UniFFI output accounts for thousands of lines, but it is read-only
  contract code rather than handwritten duplication. The target-independent Node
  binding is committed at packages/js/node/databricks/src/_bindings.ts:1;
  Python commits its generated package-root export at
  `packages/py/databricks/src/dbx_tools/databricks/__init__.py:1` while the local
  bindings.py is generated and ignored at .gitignore:99-102.
- The shared/node/ui package split creates many small manifests, but it prevents
  browser code from importing Node APIs and keeps optional UI/runtime dependencies
  out of contract packages. AGENTS.md:804-812 documents the intended wall.
- shared-core declarations with no literal source import look removable, but the
  generator deliberately makes shared-core a dependency of every package and
  requires it to stay dependency-light; AGENTS.md:811-812 is the source of truth.
- @dbx-tools/fs overlaps Mastra 1.47.0, pinned at package.json:150, including
  LocalFilesystem containment and lifecycle at
  node_modules/@mastra/core/dist/workspace/filesystem/local-filesystem.d.ts:17-59
  and :104-214. It still earns its boundary as the Node implementation of the
  shared-fs contract and its host-path policy; AGENTS.md:820-829 says to keep it.
- Node AppKit and Rust both parse Lakebase addresses. The Node bootstrap must
  remain native-free, and parity tests are the appropriate enforcement mechanism;
  docs/enhancements/dry-code-quality-audit.md:57-63 records that decision.

  event vocabulary. AppKit ^0.60 is catalogued at package.json:144 and installed

  simplifies the stream response
  and does not expose thought snapshots, so deleting the package today would
  remove behavior, not just code; compare
  packages/js/shared/genie/src/genie-model.ts:68-214 with
  node_modules/@databricks/appkit/dist/shared/src/genie.d.ts:2-28.
- UI Mastra's small stream parser mirrors the pinned Mastra client 1.28.0 at
  package.json:170 because the stock approval-resume path can reject a
  tool-result without a new tool-call. Compare
  packages/js/ui/mastra/src/support/mastra-stream.ts:18-62 with the public
  client's parser and approval flow at
  node_modules/@mastra/client-js/dist/index.js:368-432, :1896-1906, :1948-1995,
  and :2336-2359. Keep the compatibility shim until the public client covers
  that flow.
- Raw pgwire startup and cancellation code is not a reinvention that a higher
  pgwire API currently covers. Keep
  packages/rs/lakebase-proxy/src/proxy/startup.rs:89-190 and
  packages/rs/lakebase-proxy/src/proxy/cancellation.rs:20-115.

  packages/rs/databricks/src/oauth/flow.rs:221-291 is necessary even with the

  local callback server.
- scripts/install.ts is large, but it is the dependency-free standalone seam

  scripts/install.test.ts:1. Prune parallel installer surfaces, not this owner.
- The six tracked Rust crates and five Python distributions look granular. The
  newly landed OpenAPI generator/client pair was excluded while in progress and

  audited packages likewise isolate native artifacts, optional cloud libraries,
  executable protocols, or framework dependencies. Merging them would increase
  consumer installation cost without deleting the underlying implementation.
